# 餐厅收藏

## 功能名称：餐厅收藏

### 功能描述

在实验 7-1 美食助手的基础上，为用户增加餐厅收藏功能。每个餐厅卡片上显示收藏图标，用户点击后可收藏/取消收藏，收藏的餐厅在右侧新增的"我的收藏"面板中展示。

### 输入

- 餐厅 ID：string，必填
- 操作类型：add / remove，必填

### 输出

- 收藏成功：图标变为实心❤️，toast 提示"已添加收藏"
- 取消收藏：图标变为空心❤️，toast 提示"已取消收藏"
- 操作失败：toast 提示"操作失败，请重试"

### 约束条件

- 最多收藏 20 家餐厅，超出时提示"收藏夹已满（最多20家）"
- 收藏数据使用 localStorage 持久化存储，页面刷新后状态保持
- 同一餐厅不能重复收藏
- 新增"我的收藏"面板位于页面右侧、地图下方
- 收藏面板中点击餐厅，地图自动定位到该餐厅并弹出详情

### 新增约束（第 3 轮 · 规范约束增强）

本小节在原"约束条件"之上叠加校验、安全与代码规范要求。新增条目与原约束同时生效，不替换、不削弱任何既有约束与既有验收标准。

#### 校验规则：餐厅 ID 合法性

1. **类型与非空**：餐厅 ID 必须是字符串类型且非空。系统应在进入收藏/取消收藏业务逻辑之前完成校验，校验未通过时不得进入后续流程。
2. **无效判定**（满足任意一条即判定为无效）：
   a. ID 为 undefined、null 或非字符串类型（数字、布尔、对象、数组等）；
   b. ID 为字符串但裁剪首尾空白后为空串；
   c. ID 为字符串但无法对应到当前已加载的任一餐厅。
3. **无效数据的处理**：系统禁止写入 localStorage；禁止修改内存中的收藏列表（不得新增、删除或改变顺序）；禁止刷新或改变收藏面板与卡片图标状态；禁止弹出"已添加收藏""已取消收藏"等成功提示；必须通过 `console.warn` 输出告警，告警内容应包含问题语义与原始入参，便于定位。
4. **有效数据的处理**：系统应照常执行原有 add/remove 流程，包括重复收藏判断、20 家上限判断、持久化写入与 toast 提示，行为与第 1 轮一致。
5. **失败提示边界**：原有"操作失败，请重试"提示仅用于存储写入失败等运行期异常；参数校验失败一律走 `console.warn`，不得以成功提示或误导性提示代替。

#### 安全约束：XSS 过滤

1. **过滤范围**：收藏数据中所有来源于餐厅数据的文本字段，即 `name`、`taste`、`address`。`id` 作为收藏与餐厅的关联标识，必须保持与原餐厅一致，不得因过滤导致 id 被改写而使收藏失联；`price`、`lng`、`lat`、`addedAt` 为数值/时间字段，不做文本过滤，但读取时须校验类型合法性。
2. **写入前过滤**：在写入 localStorage 之前，系统必须对上述文本字段执行 XSS 过滤，清除或转义可执行脚本内容（如 `<script>` 标签、`on*` 事件属性、`javascript:` 伪协议等）。
3. **读取时清洗**：从 localStorage 读取收藏数据时，系统必须对每个文本字段再次执行清洗；清洗后字段不合法或条目结构不合法的数据按脏数据忽略或剔除，禁止将原始脏数据直接渲染。
4. **渲染兜底**：收藏面板与餐厅卡片的文本渲染必须以纯文本方式输出，禁止将存储内容当作 HTML 解析执行，确保即使存在绕过过滤的脏数据也不会被执行。
5. **保真要求**：过滤不得改变正常中文文本（汉字、中文标点、顿号、括号、空格等）与合法可见字符；不得导致正常餐厅名称、口味、地址被截断、乱码、丢字或语义改变。
6. **非阻断要求**：过滤过程发生异常时不得中断收藏主流程，也不得阻断页面初始化。

#### 代码规范

1. **ES6 语法**：全面使用 ES6+ 语法——以 `const`/`let` 替代 `var`，以箭头函数替代传统函数表达式，以模板字符串替代字符串拼接。
2. **JSDoc 注释**：每个函数（含校验工具 Validator、XSS 过滤工具 XSSFilter）必须添加 JSDoc 注释，说明功能、参数（类型与含义）、返回值。
3. **命名规范**：变量与函数使用小驼峰 camelCase（如 `validateRestaurantId`、`sanitizeFavoriteFields`），常量使用全大写下划线（如 `FAVORITES_LIMIT`）。
4. **事件绑定**：事件监听统一使用 `addEventListener`，禁止使用 HTML 内联 `onclick`/`onchange` 等 `on*` 属性绑定。
5. **零依赖**：禁止引入构建工具与第三方依赖，保持原生 HTML/CSS/JS 实现。

#### 功能保持不变（回归基线）

1. 单餐厅收藏与取消收藏、图标空心/实心切换、toast 文案"已添加收藏"/"已取消收藏"保持不变。
2. 最多收藏 20 家及"收藏夹已满（最多20家）"提示保持不变。
3. 收藏数据使用 localStorage 持久化、刷新页面后状态保持、与"最近搜索"存储项相互独立，均保持不变。
4. "我的收藏"面板位于页面右侧、地图下方，计数展示与空态展示保持不变。
5. 点击收藏面板中的餐厅触发地图定位并弹出详情保持不变。
6. 桌面端左右分栏、移动端上下堆叠的响应式布局保持不变。
7. 原有 6 条验收标准全部继续通过。

### 验收标准

- [ ] 每个餐厅卡片上显示收藏图标（空心/实心）
- [ ] 点击图标可正常添加/取消收藏
- [ ] 刷新页面后收藏状态保持
- [ ] 收藏超过 20 家时提示上限
- [ ] "我的收藏"面板正确显示列表
- [ ] 点击收藏列表餐厅，地图定位并弹出详情
### 新增验收标准（第 3 轮 · 规范约束增强）

**校验规则**
- [ ] 传入数字、布尔、对象、数组、null 或 undefined 作为餐厅 ID 执行收藏时，不写入存储、不改变内存收藏列表、不弹成功提示，且控制台出现 `console.warn`。
- [ ] 传入空字符串或仅含空白字符的餐厅 ID 时，不写入存储、不改变内存收藏列表、不弹成功提示，且控制台出现 `console.warn`。
- [ ] 传入不存在于当前餐厅列表的字符串 ID 时，收藏项数量与顺序不变，卡片图标不变，且控制台出现 `console.warn`。
- [ ] 传入合法字符串 ID 时，收藏/取消行为、图标切换与 toast 提示与原有逻辑完全一致。
- [ ] 无效 ID 场景下，页面不出现"已添加收藏""已取消收藏"等任何成功类提示。

**XSS 过滤**
- [ ] 收藏写入 localStorage 前，`name`、`taste`、`address` 中的 `<script>`、`on*` 事件属性、`javascript:` 等危险内容被过滤或转义，存储中不再包含可执行脚本。
- [ ] 含危险片段的餐厅名称/口味/地址收藏后，正常中文字符与合法标点保持不变，不出现乱码、丢字或截断。
- [ ] 手工向 localStorage 注入含 `<script>` 或事件属性的脏收藏数据后刷新页面，脚本不执行、页面不报错，脏字段被清洗，其余合法收藏仍正常展示。
- [ ] 手工注入非字符串 `id`、缺失文本字段或结构非法的脏收藏条目后刷新，页面不报错，非法条目被忽略或剔除。
- [ ] 收藏面板与卡片以纯文本渲染存储内容，不将存储内容解析为 HTML 执行。
- [ ] 读取清洗与写入过滤均生效：先写入脏数据再刷新、以及直接注入脏数据两条路径均不出现脚本执行。

**代码规范**
- [ ] 收藏相关代码使用 `const`/`let`、箭头函数、模板字符串，无残留 `var` 与传统字符串拼接。
- [ ] 每个函数（含 Validator、XSSFilter）均带有 JSDoc，覆盖功能、参数类型与含义、返回值。
- [ ] 变量与函数使用小驼峰命名，常量使用全大写下划线命名。
- [ ] 事件监听统一使用 `addEventListener`，HTML 中不存在 `onclick`/`onchange` 等内联事件属性。

**功能保持不变（回归）**
- [ ] 单次收藏/取消收藏、空心/实心图标切换、成功 toast 文案与第 1 轮一致。
- [ ] 收藏达到 20 家后再收藏，提示"收藏夹已满（最多20家）"，且不新增收藏项。
- [ ] 刷新页面后收藏状态与顺序保持；收藏存储项与最近搜索存储项互不影响。
- [ ] "我的收藏"面板位置、计数展示与空态展示不变。
- [ ] 点击收藏列表中的餐厅，地图仍能定位并弹出详情。
- [ ] 桌面端左右分栏、移动端上下堆叠布局不变。
