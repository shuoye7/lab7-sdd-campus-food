# 最近搜索

## 功能名称：最近搜索

### 功能描述

在实验 7-1 美食助手既有搜索能力之上，为搜索框补充"最近搜索"能力。用户每次提交非空关键词后，系统自动记录该关键词；在搜索框正下方以标签形式展示最近使用过的关键词（最近优先），支持点击一键复用搜索与整体清空。记录保存在浏览器本地，刷新页面后保持。

本功能只负责关键词的记录、展示、复用与清空，不改变 `searchPlaces()` 既有搜索链路、筛选、排序、地图与详情展示逻辑。不提供搜索联想/自动补全，不记录筛选条件、排序方式或搜索时间，不上传任何数据到服务端。

### 输入

- 搜索关键词：string，来自搜索表单提交（点击"搜索"按钮或按回车），必须先裁剪首尾空白；裁剪后为空视为未输入。
- 最近搜索项点击：string，用户在"最近搜索"区域内点击某一个已记录的关键词。
- 清空指令：动作，用户点击"最近搜索"区域内的"清空"按钮。

同一次搜索提交无论底层走高德 REST 还是示例数据，均视为同一输入事件，记录规则一致。

### 输出

- "最近搜索"区域：位于首页搜索框正下方、筛选栏上方，按最近使用倒序展示关键词标签，最多 8 个；无记录时不渲染该区域。
- 复用搜索：点击某个条目后，关键词回填搜索框并立即触发一次搜索，结果列表、结果计数与地图按既有逻辑刷新，该关键词同时提升至记录首位。
- 清空结果：区域整体隐藏，本地记录被删除，并给出 toast 提示"已清空最近搜索"。
- 持久化结果：刷新或重新打开页面后，区域内容与顺序与关闭前一致。
- 存储异常：不阻断搜索、不弹出错误提示，页面表现为该区域按当前可用数据展示或不展示。

### 约束条件

1. **记录时机**：当用户提交的关键词裁剪首尾空白后非空时，系统应将该关键词写入最近搜索记录；当关键词为空或仅含空白时，系统应保持既有记录不变，禁止写入空串。
2. **记录范围**：当用户仅切换价格筛选、口味筛选或排序方式时，系统不应产生任何最近搜索记录。
3. **去重与顺序**：当待记录的关键词在已有记录中存在（忽略首尾空白差异）时，系统应将其移动到记录首位且条目不增加；否则应作为新条目插入首位。
4. **数量上限**：记录条数上限为 8；当插入新条目使总数超过 8 时，系统应自动丢弃最久未使用的一条。
5. **持久化与隔离**：系统应将会话记录写入浏览器本地存储，且与"餐厅收藏"使用相互独立的存储项；当页面刷新或重新打开时，系统应恢复为最后保存的内容与顺序。
6. **展示规则**：当存在记录时，系统应在搜索框下方展示"最近搜索"区域，最多展示 8 个关键词；当无记录时，系统应完全隐藏该区域，禁止显示占位空态或残留空白，且不得引起布局跳动。
7. **复用规则**：当用户点击某个最近搜索条目时，系统应将该关键词填入搜索框、立即发起搜索，并把该关键词提升到记录首位。
8. **清空规则**：当用户点击"清空"时，系统应一次性删除全部记录、隐藏该区域并提示"已清空最近搜索"；本功能不提供单条删除能力。
9. **数据清洗**：当本地存储中的记录损坏、非数组或条目结构不合法时，系统应忽略脏数据并按无记录处理，禁止因此中断页面初始化或报错。
10. **长度约束**：当单个关键词长度超过 50 个字符时，系统应照常以其完成搜索，但记录时仅保留前 50 个字符。
11. **禁止项**：本功能禁止新增后端接口、构建工具、第三方依赖或任何网络请求；禁止将最近搜索数据上传服务端；禁止记录筛选条件、排序方式、搜索时间与点击过的餐厅。

### 新增约束（第 3 轮 · 规范约束增强）

本小节在原"约束条件"之上叠加校验、安全与代码规范要求。新增条目与原约束同时生效，不替换、不削弱任何既有约束与既有验收标准。

#### 校验规则：输入合法性

1. **类型与非空**：搜索关键词、最近搜索条目的触发值必须是字符串类型且非空。系统应在进入记录/复用/清空业务逻辑之前完成校验。
2. **无效判定**（满足任意一条即判定为无效）：
   a. 值为 undefined、null 或非字符串类型（数字、布尔、对象、数组等）；
   b. 值为字符串但裁剪首尾空白后为空串；
   c. 点击复用时的条目值在当前记录中匹配不到任何条目。
3. **无效数据的处理**：系统禁止写入 localStorage；禁止修改内存中的最近搜索记录（不得新增、去重提升、删除或改变顺序）；禁止触发搜索；禁止弹出"已清空最近搜索"等成功类提示；必须通过 `console.warn` 输出告警，告警内容应包含问题语义与原始入参。
4. **有效数据的处理**：系统应照常执行原有记录、去重、8 条上限、复用与清空流程，行为与第 1 轮一致，包括去重项提升至首位、超出 8 条时丢弃最久未使用项。
5. **清洗顺序**：记录一条关键词时，应先裁剪首尾空白，再执行 XSS 过滤，最后按过滤后的结果计算长度上限与去重键。

#### 安全约束：XSS 过滤

1. **过滤范围**：最近搜索的全部记录内容（每条记录均为一个关键词字符串），包括用户提交并落库的关键词以及读取到的历史关键词。
2. **写入前过滤**：在写入 localStorage 之前，系统必须对关键词执行 XSS 过滤，清除或转义可执行脚本内容（如 `<script>` 标签、`on*` 事件属性、`javascript:` 伪协议等）。
3. **读取时清洗**：从 localStorage 读取最近搜索记录时，系统必须逐条再次清洗；清洗后为空、结构不合法（非字符串）或无法安全展示的条目按脏数据忽略，禁止将原始脏数据直接渲染。
4. **渲染兜底**：最近搜索标签与回填到搜索框的文本必须以纯文本方式输出，禁止将存储内容当作 HTML 解析执行，确保即使存在绕过过滤的脏数据也不会被执行。
5. **保真要求**：过滤不得改变正常中文关键词（汉字、中文标点、空格、数字、字母及合法可见字符等）；不得导致正常关键词被截断、乱码或语义改变。
6. **去重与长度口径**：去重判断以过滤后的关键词为比较口径；50 字符长度上限以过滤后的关键词计，过滤不得导致正常中文关键词提前被截断。
7. **非阻断要求**：过滤过程发生异常时不得中断搜索主流程，也不得阻断页面初始化。

#### 代码规范

1. **ES6 语法**：全面使用 ES6+ 语法——以 `const`/`let` 替代 `var`，以箭头函数替代传统函数表达式，以模板字符串替代字符串拼接。
2. **JSDoc 注释**：每个函数（含校验工具 Validator、XSS 过滤工具 XSSFilter）必须添加 JSDoc 注释，说明功能、参数（类型与含义）、返回值。
3. **命名规范**：变量与函数使用小驼峰 camelCase（如 `validateKeyword`、`sanitizeKeyword`），常量使用全大写下划线（如 `RECENT_SEARCH_LIMIT`）。
4. **事件绑定**：事件监听统一使用 `addEventListener`，禁止使用 HTML 内联 `onclick`/`onchange` 等 `on*` 属性绑定（含"清空"按钮与关键词标签的点击）。
5. **零依赖**：禁止引入构建工具与第三方依赖，保持原生 HTML/CSS/JS 实现。

#### 功能保持不变（回归基线）

1. 最近搜索区域位置（搜索框正下方、筛选栏上方）、最近优先倒序展示、最多 8 个保持不变。
2. 记录时机、去重提升、超出上限淘汰最久未使用项保持不变。
3. 点击条目回填搜索框并立即复用搜索、条目提升至首位保持不变。
4. "清空"一次性删除全部记录、隐藏区域并提示"已清空最近搜索"保持不变。
5. 无记录时完全隐藏区域、无占位空白与布局跳动保持不变。
6. 存储项与"餐厅收藏"相互独立、刷新后内容与顺序保持、不上传服务端保持不变。
7. 原有 12 条验收标准全部继续通过。

### 验收标准

- [ ] 当用户提交非空关键词（如"川菜"）并完成搜索时，搜索框下方出现"最近搜索"区域并包含"川菜"。
- [ ] 当用户依次搜索"川菜"→"日料"→"奶茶"时，区域顺序为"奶茶、日料、川菜"（最近优先）。
- [ ] 当用户重复搜索已记录的关键词时，记录总数不变且该关键词移动至首位。
- [ ] 当用户累计搜索超过 8 个不同关键词时，区域仅保留最近 8 个，最久未使用的一条被移除。
- [ ] 当用户提交空关键词或仅含空白字符时，不新增记录，原有记录与顺序保持不变。
- [ ] 当用户仅切换价格筛选、口味筛选或排序方式时，不产生任何最近搜索记录。
- [ ] 刷新页面或重新打开页面后，最近搜索区域的内容与顺序与刷新前一致。
- [ ] 当用户点击某个最近搜索条目时，搜索框回填该关键词、立即触发搜索并展示结果，该条目同时移至首位。
- [ ] 当不存在任何记录时，页面不展示"最近搜索"区域，且无占位空白或布局跳动。
- [ ] 当用户点击"清空"后，区域消失、刷新后仍为空，并出现"已清空最近搜索"提示。
- [ ] 当本地存储损坏或被写入非法结构时，页面不报错，搜索与筛选等既有功能仍正常工作。
- [ ] 本功能未引入任何后端接口、构建步骤或第三方依赖，最近搜索数据仅保存在本地浏览器。
### 新增验收标准（第 3 轮 · 规范约束增强）

**校验规则**
- [ ] 当传入数字、布尔、对象、数组、null 或 undefined 作为关键词时，不新增记录、不改变既有记录与顺序、不触发搜索，且控制台出现 `console.warn`。
- [ ] 当关键词为字符串但裁剪首尾空白后为空时，不写入存储、不改变既有记录，且控制台出现 `console.warn`。
- [ ] 当点击复用值在当前记录中匹配不到条目时，不发起搜索、不改变记录与顺序，且控制台出现 `console.warn`。
- [ ] 当输入合法非空字符串关键词时，记录、去重提升、8 条上限与复用行为与原有逻辑完全一致。
- [ ] 无效输入场景下，页面不出现"已清空最近搜索"等任何成功类提示。

**XSS 过滤**
- [ ] 最近搜索关键词写入 localStorage 前，`<script>`、`on*` 事件属性、`javascript:` 等危险内容被过滤或转义，存储中不再包含可执行脚本。
- [ ] 含危险片段的关键词过滤后，正常中文、中文标点、空格、数字与字母保持不变，不出现乱码、丢字或语义改变。
- [ ] 手工向 localStorage 注入含 `<script>` 或事件属性的脏关键词后刷新页面，脚本不执行、页面不报错，脏条目被清洗或忽略，其余合法记录仍正常展示。
- [ ] 手工注入非字符串条目或结构非法的存储内容后刷新页面，页面不报错，按无记录或忽略非法条目处理，搜索等既有功能正常。
- [ ] 最近搜索标签与回填搜索框的关键词以纯文本方式输出，不解析为 HTML 执行。
- [ ] 写入前过滤与读取时清洗均生效，两条路径均不出现脚本执行；去重与 50 字符上限以过滤后的关键词为口径。

**代码规范**
- [ ] 最近搜索相关代码使用 `const`/`let`、箭头函数、模板字符串，无残留 `var` 与传统字符串拼接。
- [ ] 每个函数（含 Validator、XSSFilter）均带有 JSDoc，覆盖功能、参数类型与含义、返回值。
- [ ] 变量与函数使用小驼峰命名，常量使用全大写下划线命名。
- [ ] 事件监听统一使用 `addEventListener`，HTML 中不存在 `onclick`/`onchange` 等内联事件属性。

**功能保持不变（回归）**
- [ ] 最近搜索区域位置、最近优先倒序、最多 8 个展示与第 1 轮一致。
- [ ] 去重提升至首位、超出 8 条淘汰最久未使用项的行为不变。
- [ ] 点击条目回填搜索框并立即复用搜索的行为不变。
- [ ] "清空"一次性删除全部记录、隐藏区域并提示"已清空最近搜索"的行为不变。
- [ ] 无记录时区域完全隐藏，无占位空白与布局跳动。
- [ ] 刷新后内容与顺序保持，存储项与"餐厅收藏"相互独立，数据不上传服务端。
- [ ] 页面仍为零依赖原生实现，未新增后端接口、构建步骤或第三方依赖。
